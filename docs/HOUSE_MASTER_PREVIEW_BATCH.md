# Bounded Automatic House Mastering Preview: Cross-Prompt Experiment

**Status:** **implemented, technically verified preview derivation, not a professional-quality master.** This is a reusable post-processing step for Kuang's genuine, immutable, editable native SoundCraft + Vital house template, not a per-song mastering instruction and not an algorithmic subjective winner.

## General-purpose algorithm

Module: `kuang.house_master_preview`; optional integrated private creation mode: `kuang.autonomous_create --groove-template --master-preview`.

1. Validate the original native editable session exists and previously passed native save/reopen, source PCM hashes and original loudness/true-peak receipts. Reject silence, clipping, invalid 48-kHz/24-bit stereo, mismatched evidence or unsupported duration (2–600 s).
2. Measure exact 4× FIR true peak and BS.1770 K-weighted integrated loudness, using Kuang's previously audited pure-Python backend or an explicitly provided private libebur128 1.2.6 reference library.
3. Make **A: gain-only** by applying the lesser of 12 dB and unused headroom up to **−1.7 dBTP**. This preserves every note, all source relative instrument gains, crest factor and DSP dynamics. It does **not** solve source/arrangement or masking.
4. Make **B: gentle compressed** with a real linked stereo 1.3:1 compressor, 15-ms attack and 150-ms release. Threshold is bounded to −38…−12 dBFS based on the *actual input sample peak*, not on an assumed absolute mix level. Apply a separately measured gain to −1.7 dBTP or a +12 dB ceiling. This is intentionally mild and *not* a brickwall limiter.
5. Individually measure each result. **Fail closed** if the final sample clips, true peak exceeds −1.1 dBTP, sample count/format changes, or integrated loudness drops unexpectedly. Verify original source WAV hash unchanged.
6. Retain original **native editable session and premix WAV**; put the two offline 24-bit stereo derivatives and `master-preview-report.json` in a separate private folder. `preferred_mode: null`, `producer_ready: false`, `perceptual_quality: NEEDS_LISTENING`. Do not choose a winner from LUFS or the amount of compression.

This approach correctly handles the prior multi-prompt batch whose native premixes had substantial but inconsistent peak headroom. A *technical* change in loudness is not proof of better groove, clearer bass, more pleasing chords or professional mastering.

### Generic opt-in command

```bash
# Process an already verified local private source without rerunning Vital auditions.
PYTHONPATH=/path/to/Kuang python3 -m kuang.house_master_preview \
  --source-dir /private/workspace/verified-house-output \
  --out-dir /private/workspace/new-master-preview \
  --library /private/workspace/producer/libebur128.so
```

Or request preview mastering in the independent, private one-prompt generator:

```bash
python3 -m kuang.autonomous_create \
  "classic house in A minor, 125 bpm, 16 bars, no lead, without pad" \
  --catalog /private/preset-library/catalog.json \
  --plugin /private/pinned/vitalium.vst3 \
  --soundcraft /path/to/reviewed/soundcraft-cli \
  --out-dir /new/private/session \
  --private-third-party-presets --groove-template \
  --sample-pack /private/verified/house-core \
  --master-preview --max-candidates 8 --per-role 1 --timeout 25
```

The `--master-preview` flag is deliberately opt-in while this preview pipeline and broader audio source selection are being evaluated; the existing default generation behavior is unchanged. For long-form arrangements, the same algorithm supports up to 600 s, but CPU cost scales with render length and remains bounded by external shell execution limits.

## Real cross-prompt results — November 13, 2026

Each actual `preview.wav` was generated by **different independently selected Vital presets and CC0 sample kits**. Native sources remained unchanged; mastering derivatives are derived offline, so an engineer can reproduce the exact DSP with the recipes. Measurements use an explicitly provided local libebur128 1.2.6 reference backend, **not commercial/mastering certification**.

| Style | Raw premix LUFS-I / dBTP | Gain-only LUFS-I / dBTP | Gentle LUFS-I / dBTP | Processing outcome |
|---|---|---|---|---|
| Deep Dm /124 | −25.65 / −10.58 | **−16.78 / −1.70** | −17.29 / −1.70 | Gain-only louder; compression did not improve measured crest |
| Jackin Fm /126 | −30.58 / −12.68 | **−19.60 / −1.70** | −19.74 / −1.70 | Gain-only slightly louder; high crest remains |
| Minimal Gm /122 | −28.01 / −9.12 | −20.59 / −1.70 | **−20.17 / −1.70** | Gentle compression increased loudness slightly and reduced crest |

Every variant passed 48-kHz/24-bit stereo unchanged frame count, nonzero material, 0 clipped samples, bounded peak checks. The gain-only crest remains **19.84 dB, 22.02 dB, 24.11 dB** for deep, jackin and minimal; the gentle version measured **20.31 dB, 22.14 dB, 23.67 dB**.

**Interpretation:** Master processing can close unused peak headroom, but raw profile-dependent sound choice and mix dynamics still produce ~3.8 LU of variation across the three gain-only outputs. A single global loudness or compression preset is **not** a substitute for contextual source choice and per-role balancing.

## Next generalization gates

1. Add candidate-level evidence for **kick attack duration, bass upper harmonic energy and actual overlap windows** rather than simple 20–120 Hz spectrum totals.
2. Establish conservative automated *reject/fix* policies for genuine problems (phase cancellation, accidental silence, excessive sub masking, inconsistent drum sampler levels) with original/modified A/B evidence.
3. Keep the output separated as **edit-ready native premix plus clearly marked preview master**, and do not call the preview finished.
4. Run several independent multi-prompt/seed batches under bounded cost; select/repair poor candidate combinations before doing a full-length 128-bar render.
5. For final product review, supply audio through the conversation in an accessible playable form. **The user does not need to listen to VPS-only engineering files or manually supervise routine tests.** The assistant cannot honestly claim to have heard remote audio merely by analyzing metrics.

A master stage that passes meters has achieved *technical delivery hygiene*, not a validated high-quality house production. The quality review remains separate.
