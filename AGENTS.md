# Operational context

**Primary product direction:** Kuang is a one-prompt, producer-ready **house template generator** that should complete most repetitive groove/arrangement/sound-selection/mix/master work while preserving full musical and DAW editability. Quality, reliability and ease of customization take priority over uniqueness or autonomous songwriting. The user's '80% complete' language is an aspirational workflow outcome, not an invented numerical quality score. Read `docs/PRODUCER_READY_TEMPLATE_PRODUCT.md` first, then `docs/HOUSE_PRODUCTION_PLAYBOOK.md`, `docs/HOUSE_GROOVE_STANDARDS.md`, and `docs/HOUSE_STYLE_STANDARDS.md`. Its 75 reference-derived checks and 40 cross-cutting house standards distinguish implemented capabilities from proposals and technical validity from actual listening approval. The Phase43/44 main reference is a quality baseline, not a license to copy its music or a mandatory song template. Keep the phase-specific reference states intact. Also read `docs/HOUSE_REFERENCE_CASE_STUDIES.md` and `docs/HOUSE_REFERENCE_TRACKS.json` for external hit-track studies. These only support abstract, source-qualified groove and arrangement patterns: never copy a track's signature bassline, lead, samples, presets or MIDI, and never mistake a third-party remake for the artist's original DAW session.

## Current implementation

- Python >=3.11; runtime standard library only. Run from this checkout with `python3 -m kuang`.
- Phase 2 `create` is prompt → strict SongSpec v1 (`song.py`) → deterministic `composer.py` → canonical/MIDI and optional verified SoundCraft/render. Preserve the separate Phase 0 generator and fixtures. SongSpec is not a canonical schema migration.
- Phase 4 `create --production refined` applies `production.py` to the existing house sketch: deterministic seventh voicings, call/response, swing, synth envelopes, insert FX and independent native FX/mixer lanes. Default sketch bytes and schema 0.1 remain unchanged. Normalized Choice positions must map to integer selectors; `soundcraft.decay_ms` converts ms to native seconds. Never interpolate discrete plugin controls or relabel pitch/ratio/Q units. No native synth automation/LFO/wavetable claim. `production_audio.py` supplies sampled Hann FFT band fractions and section/stereo/crest metrics, not perceptual quality scores. `tools/phase4_reference.py` writes fresh labeled native A/B, RMS-matched audition copies and full source hash inventories into new artifact directories.
- Phase 3 `revise` edits existing directories through `revision.py` (ChangeIntent/RevisionPlanner, strict semantic compilation, per-intent scopes and receipt-chain replay) and `revise.py` (staging, source drift/inventory, full native comparison and measured A/B). `--plan-only` is a read-only review; `--plan` recompiles and verifies the reviewed data against its hash. Canonical schema and core transaction operations remain unchanged.
- Revisions preserve original metadata/SongSpec as provenance and write new plan/receipt/report sidecars. Never interpret absent section names as aliases (Phase 2 has Main, not Verse), ignore unknown prose, merge scopes into a broader time allowance, or accept effects/parameters that do not already exist. Reject base changes overridden by automation. Existing `undo`/`redo` support the strictly validated `revision-1` wrapper of ordinary scoped receipts.
- Rules planning is heuristic and must report `ai_plan: false`. Optional `local_planner.py` uses only fixed loopback Ollama HTTP, bounded structured output, the reviewed installed Apache-2.0 `qwen3.5:4b`, and no model downloads or fallback. Reject FIRM/cloud models and `qwen2.5:3b-instruct` (research license). Keep explicit tempo/key/seed/bar constraints checked after inference.
- Ollama is an optional experiment/benchmark, not assumed primary musical intelligence. Future optional stronger Codex CLI/other-provider planning must use the same strictly validated SongSpec/typed operations; inference costs/accounts/terms stay separate and optional. Do not recursively invoke Codex from a Codex development session. Do not expand Phase 2 into a provider backend; benchmark quality before claiming superiority.
- Canonical `.kuang.json` schema version `0.1` is authoritative. See `docs/ARCHITECTURE.md` before changing timing, IDs, validation or transactions.
- `kuang/schema.py`: dataclasses, strict JSON, validation, canonical hashes, atomic file replacement.
- `kuang/transactions.py`: typed operations, scope/locks, atomic candidate apply, inverse receipts/history.
- `kuang/generator.py`, `midi.py`, `engines.py`: seeded symbolic arrangement, type-1 writer, model proposal boundary.
- `kuang/reaper.py`, `reaper_adapter.lua`: data-only import plan and native editable host objects.
- `kuang/adapters.py`: DAWAdapter Protocol. `kuang/soundcraft.py` is the primary optional SoundCraft 0.11.0 backend; `soundcraft_cli.py` exposes native bundles, explicit snapshot import, staged edits, inspection/save and WAV export. `audio.py` measures integer PCM WAVs.
- SoundCraft CLI has real headless save/reopen/render coverage. It remains an external user-installed executable: discover with `describe` and `engine.plugins`, use subprocess argv, enforce the version/build/contract pin and reject unsupported mappings. Never edit native JSON directly to synthesize host support.
- `examples/soundcraft-demo.kuang.json` explicitly selects built-ins. Preserve the original Phase 0 demo and its hashes. Native notes have no IDs and MIDI clips merge; retain canonical IDs in the bundle manifest. Import is verified snapshot recovery, never automatic reconciliation of host edits.
- No REAPER process or Vital installation was available for Phase 0. Mock/API-contract tests do not establish real host compatibility or audio quality.
