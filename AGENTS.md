# Operational context

**Primary product direction:** Kuang is a one-prompt, producer-ready **house template generator** that should complete most repetitive groove/arrangement/sound-selection/mix/master work while preserving full musical and DAW editability. Quality, reliability and ease of customization take priority over uniqueness or autonomous songwriting. The user's '80% complete' language is an aspirational workflow outcome, not an invented numerical quality score. Read `docs/PRODUCER_READY_TEMPLATE_PRODUCT.md` first, then `docs/HOUSE_PRODUCTION_PLAYBOOK.md`, `docs/HOUSE_GROOVE_STANDARDS.md`, and `docs/HOUSE_STYLE_STANDARDS.md`. Its 75 reference-derived checks and 40 cross-cutting house standards distinguish implemented capabilities from proposals and technical validity from actual listening approval. The Phase43/44 main reference is a quality baseline, not a license to copy its music or a mandatory song template. Keep the phase-specific reference states intact. Also read `docs/HOUSE_REFERENCE_CASE_STUDIES.md` and `docs/HOUSE_REFERENCE_TRACKS.json` for external hit-track studies. These only support abstract, source-qualified groove and arrangement patterns: never copy a track's signature bassline, lead, samples, presets or MIDI, and never mistake a third-party remake for the artist's original DAW session.

**First actual cross-prompt native production batch, 2026-11-13:** Three *distinct* 16-bar private CC0+Vital outputs passed real SoundCraft reopen/format/zero-clipping checks (deep Dm 124 BPM, jackin Fm 126 BPM, minimal Gm 122 BPM). All three selected different drum kits/groove fingerprints/private bass/chord presets, but **none met conservative near-finished mix-level warnings**: integrated -25.65/-30.58/-28.01 LUFS, TP -10.58/-12.68/-9.12 dBTP, crest 19.84/22.02/24.11 dB. Their groove-section spectra differ strongly; isolated metric compliance is *not* production quality. `kuang.house_batch_acceptance` is the reusable 2–8 candidate audit harness; see `docs/HOUSE_CROSS_PROMPT_BATCH_20261113.md` for exact evidence. Do not request the user's final listening test until genuinely chat-playable files are available and the reusable output/master workflow passes technical gates; the user cannot listen to VPS-only files. The assistant has **not subjectively listened** to these remote WAVs and must not claim it did. Prioritize autonomous source compatibility, controlled premaster/master preview and multi-prompt regression over personal iteration on any individual reference.

**Generalized full-length arrangements (new):** `kuang/house_full_arranger.py` is an opt-in, originally authored, reusable **96/112/128/160-bar** arranger; it maps a verified 32-bar source (four eight-bar musical regions) into full Intro/Groove A/Groove B/Break/Build/Drop/Return/Outro using role-presence/automation rules, retains all original bass/kick pitches and groove note timings, and removes empty optional roles. Use `--production groove-template --full-song-bars 128` (symbolic/native) or private `autonomous_create --groove-template --full-song-bars 128` (third-party Vital states still private). See `docs/HOUSE_FULL_SONG_ARRANGER.md`. Test broad prompt/key/seed/form matrices, not one bespoke song. **The user cannot listen to VPS-local files and is NOT expected to approve engineering renders.** Build autonomous, reproducible generation and programmatic technical checks; ask for human listening only for a genuinely optional, user-accessible listening task. Passing technical gates is not a professional sound-quality verdict.

**More defensible mix diagnostics:** `kuang/house_mix_spectrum.py` computes absolute, frequency-resolved 20–120/120–500/500–2000/2000–8000/8000+ Hz power from genuine native stem WAVs. Initial real measurement: kick 97.7% and bass 83.2% of analyzed energy below 120 Hz, chords just 0.02% under 120 Hz. The old full-band chord-vs-kick RMS goal was not psychoacoustically valid and is **no longer applied by default**: `kuang.house_mix_roles` defaults to diagnostics-only; old fader changes need `--apply-fullband-heuristic`. `kuang.house_mix_review` creates strict attenuation-only matched-level A/B WAVs with no winner, preserving private sources. See `docs/HOUSE_SPECTRAL_AND_AB_REVIEW.md`; do not claim perceptual success or repackage private Vital sounds publicly.

**Measured mix calibration:** `kuang/house_mix_roles.py` implements an independent, opt-in, private-source-preserving three-role kick/bass/chord calibration with actual pinned SoundCraft solo render measurement over the Groove section. It changes only bounded faders and existing gain envelopes, then rerenders and saves native output with a separate <=6 dB output staging move. Consult `docs/HOUSE_MIX_ROLE_CALIBRATION.md`. Even if the native/clip tests pass, the **actual prototype hit its chord correction cap and the residual balance heuristic is NOT MET**. Do not call it an approved or mastered mix; require listening and additional adaptive balance work.

**Real-source opt-in house template:** `kuang/house_sources.py` supports a supplied local audited `house-core` CC0 kit, deterministic 44.1k→48k content-addressed sample conversion, separate kick/clap/closed-hat/open-hat/percussion native samplers, and two fully rendered (but **unranked**) SoundCraft candidates. The private `kuang/autonomous_create.py --private-third-party-presets --groove-template --sample-pack` path adds the existing pinned Vitalium chord/bass/pad audition and a single licensed drum kit to one native session. All foreign preset outputs **remain private**, user-supplied pack/license provenance is explicit, and native/PCM success is not a human quality verdict. Consult `docs/HOUSE_REAL_SOURCES_MVP.md`. Do not change the default public adapter or copy source assets into GitHub.

**Current opt-in template development:** `kuang/house_template.py` and `kuang/house_harmony.py` introduce a curated 8/16/32-bar house groove with *two* supported harmonic treatments (`simple` triads and `extended` diatonic sevenths); `--production groove-template --harmony-profile auto|simple|extended` leaves the legacy sketch/refined paths unchanged. The separate G1/G2 receipts are technical structural evidence with `NEEDS_LISTENING` quality status. Unsupported explicit modal requests fail closed; actual sampled drums/Vital presets, full-length arrangement and automatic mix/master quality calibration remain unimplemented. Do not merge this branch without relevant tests and native audio verification.

**Commercial harmonic references:** `docs/HOUSE_HARMONY_REFERENCE_STUDY.md` and `docs/HOUSE_HARMONY_REFERENCES.json` contain seven crowdsourced Hooktheory song analyses, source uncertainties and HX01–HX12 proposed gates. Read them when designing harmony/arrangement; never claim these are human quality scores, verified original DAW files, or full-bar arrangement evidence. Keep the SongSpec major/natural-minor limitation explicit, and preserve the opt-in no-melody product scope.

Kuang is an audio engineering / desktop DAW project. Preserve local-first operation, reproducibility, human editability and exact edit semantics. Do not pivot to a web SaaS or waveform-only generator.

## Current implementation

- Python >=3.11; runtime standard library only. Run from this checkout with `python3 -m kuang`.
- Phase 2 `create` is prompt → strict SongSpec v1 (`song.py`) → deterministic `composer.py` → canonical/MIDI and optional verified SoundCraft/render. Preserve the separate Phase 0 generator and fixtures. SongSpec is not a canonical schema migration.
- Phase 4 `create --production refined` applies `production.py` to the existing house sketch: deterministic seventh voicings, call/response, swing, synth envelopes, insert FX and independent native FX/mixer lanes. Default sketch bytes and schema 0.1 remain unchanged. Normalized Choice positions must map to integer selectors; `soundcraft.decay_ms` converts ms to native seconds. Never interpolate discrete plugin controls or relabel pitch/ratio/Q units. No native synth automation/LFO/wavetable claim. `production_audio.py` supplies sampled Hann FFT band fractions and section/stereo/crest metrics, not perceptual quality scores. `tools/phase4_reference.py` writes fresh labeled native A/B, RMS-matched audition copies and full source hash inventories into new artifact directories.
- Phase 3 `revise` edits existing directories through `revision.py` (ChangeIntent/RevisionPlanner, strict semantic compilation, per-intent scopes and receipt-chain replay) and `revise.py` (staging, source drift/inventory, full native comparison and measured A/B). `--plan-only` is a read-only review; `--plan` recompiles and verifies the reviewed data against its hash. Canonical schema and core transaction operations remain unchanged.
- Revisions preserve original metadata/SongSpec as provenance and write new plan/receipt/report sidecars. Never interpret absent section names as aliases (Phase 2 has Main, not Verse), ignore unknown prose, merge scopes into a broader time allowance, or accept effects/parameters that do not already exist. Reject base changes overridden by automation. Existing `undo`/`redo` support the strictly validated `revision-1` wrapper of ordinary scoped receipts.
- Rules planning is heuristic and must report `ai_plan: false`. Optional `local_planner.py` uses only fixed loopback Ollama HTTP, bounded structured output, the reviewed installed Apache-2.0 `qwen3.5:4b`, and no model downloads or fallback. Reject FIRM/cloud models and `qwen2.5:3b-instruct` (research license). Keep explicit tempo/key/seed/bar constraints checked after inference.
- Ollama is an optional experiment/benchmark, not assumed primary musical intelligence. Future optional stronger Codex CLI/other-provider planning must use the same strictly validated SongSpec/typed operations; inference costs/accounts/terms stay separate and optional. Do not recursively invoke Codex from a Codex development session. Do not expand Phase 2 into a provider backend; benchmark quality before claiming superiority.
- Canonical `.kuang.json` schema version `0.1` is authoritative. See `docs/ARCHITECTURE.md` before changing timing, IDs, validation or transactions.
- `kuang/schema.py`: dataclasses, strict JSON, validation, canonical hashes, atomic file replacement.
- `kuang/transactions.py`: typed operations, scope/locks, atomic candidate apply, inverse receipts/history.
- `kuang/generator.py`, `midi.py`, `engines.py`: seeded symbolic arrangement, type-1 writer, model proposal boundary.
- `kuang/reaper.py`, `reaper_adapter.lua`: data-only import plan and native editable host objects.
- `kuang/adapters.py`: DAWAdapter Protocol. `kuang/soundcraft.py` is the primary optional SoundCraft 0.11.0 backend; `soundcraft_cli.py` exposes native bundles, explicit snapshot import, staged edits, inspection/save and WAV export. `audio.py` measures integer PCM WAVs.
- SoundCraft CLI has real headless save/reopen/render coverage. It remains an external user-installed executable: discover with `describe` and `engine.plugins`, use subprocess argv, enforce the version/build/contract pin and reject unsupported mappings. Never edit native JSON directly to synthesize host support.
- `examples/soundcraft-demo.kuang.json` explicitly selects built-ins. Preserve the original Phase 0 demo and its hashes. Native notes have no IDs and MIDI clips merge; retain canonical IDs in the bundle manifest. Import is verified snapshot recovery, never automatic reconciliation of host edits.
- No REAPER process or Vital installation was available for Phase 0. Mock/API-contract tests do not establish real host compatibility or audio quality.

## Private autonomous house integration (November 2026)

- `autonomous_create.py` is a separate opt-in, private third-party preset workflow; it passes one validated SongSpec to `autonomous_palette.select_palette` so the selected audition key matches the composition. The palette-only CLI stays independently usable. Explicitly incompatible audition keys fail closed.
- The private integrated workflow currently requires chord and bass; an explicit `no pad` or `without pad` excludes the pad during both selection and native composition. - `refine_house(..., include_pad=True, kick_aligned_ducking=False)` retains its legacy defaults for existing experiments. The autonomous workflow explicitly opts into MIDI-kick-aligned gain pumping, not audio-triggered sidechain compression. Avoid changing older project hashes or phase fixtures.
